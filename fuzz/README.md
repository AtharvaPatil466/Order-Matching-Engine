# FIX fuzzing harness

Three fuzz targets covering the FIX wire-format surface:

| Target | Source | Exercises |
|---|---|---|
| `fuzz_fix_parser` | `fuzz_fix_parser.cpp` | `FixMessage::parse`, accessors, `validateChecksum`, `fixToOrderParams` |
| `fuzz_fix_framer` | `fuzz_fix_framer.cpp` | `FixFramer` reassembly across arbitrary fragmented chunks; asserts every emitted frame is `isWellFormed` + checksum-valid |
| `fuzz_fix_roundtrip` | `fuzz_fix_roundtrip.cpp` | `FixSerializer::buildExecutionReport` → `FixMessage::parse` round-trip; asserts field-level identity |

And one on the engine itself:

| Target | Source | Exercises |
|---|---|---|
| `fuzz_gateway_engine` | `fuzz_gateway_engine.cpp` | A client's byte stream through `TcpGateway`'s framer and `decodeFrame` into `MatchingEngine::submitOrder` (GatewayServer's shape: symbols 0 and 1, synchronous), then `OrderBook::validateIntegrity` on every book, before and after an expiry sweep. Engine asserts armed, UBSan halting. CI runs it for 10 minutes (`gateway-engine-fuzz`). |

It is compiled together with the engine sources (not linked against
`OrderMatcher`) so libFuzzer's coverage and the sanitizers reach the engine.
Its seeds are binary frames, generated rather than committed:

```bash
python3 fuzz/gen_gateway_seeds.py /tmp/gw-corpus
./fuzz/run_libfuzzer.sh gateway 60 /tmp/gw-corpus
./build-fuzz/fuzz/fuzz_gateway_engine_replay /tmp/gw-corpus   # no libFuzzer needed
```

On macOS with Homebrew LLVM, run it with
`ASAN_OPTIONS=detect_container_overflow=0`: Darwin's libFuzzer runtime shares
the program's `std::vector` code, and the mix of annotated and unannotated
instantiations trips ASan inside libFuzzer's own corpus bookkeeping on the
first input. Linux's runtime carries a private libc++, so CI runs with full
ASan.

## Two run modes

### Replay (always available)

A standalone driver that runs the harness against a corpus of files. Built
with ASan + UBSan; no libFuzzer required. Works on Apple Clang, system
GCC, anything reasonable.

```bash
cmake -S . -B build-fuzz -DBUILD_FUZZERS=ON
cmake --build build-fuzz -j --target fuzz_fix_parser_replay
./build-fuzz/fuzz/fuzz_fix_parser_replay -q fuzz/corpus
```

The corpus seeds (`fuzz/corpus/*`) are regenerated by `gen_seeds.sh`.

### Coverage-guided libFuzzer (requires Homebrew LLVM on macOS)

Apple Clang doesn't ship `-fsanitize=fuzzer`. Install Homebrew LLVM:

```bash
brew install llvm
```

Then run any target via the wrapper script — it auto-detects a
libFuzzer-capable clang, configures a dedicated `build-libfuzzer/`
tree on first run, and saves any crashes under `fuzz/crashes/<target>/`:

```bash
./fuzz/run_libfuzzer.sh parser            # 30s default run
./fuzz/run_libfuzzer.sh framer 60         # 60s
./fuzz/run_libfuzzer.sh roundtrip 0       # run until interrupted
./fuzz/run_libfuzzer.sh parser 30 fuzz/corpus  # custom corpus
```

Typical throughput on an M-series Mac with this codebase: 12k–25k
exec/s per target depending on the harness.

## Reproducing a crash

```bash
# When libFuzzer reports a crash it writes the input to fuzz/crashes/<target>/
./build-fuzz/fuzz/fuzz_fix_parser_replay fuzz/crashes/parser/crash-abc123
```

The replay binary uses ASan + UBSan, so the crash output identifies the
exact undefined behavior or memory error.

## Adding a new target

1. Write `fuzz_<name>.cpp` with `extern "C" int LLVMFuzzerTestOneInput(...)`.
2. Add to `fuzz/CMakeLists.txt`:
   ```cmake
   add_replay_target(fuzz_<name>_replay  fuzz_<name>.cpp)
   if(HAVE_LIBFUZZER)
       add_libfuzzer_target(fuzz_<name>  fuzz_<name>.cpp)
   endif()
   ```
3. Optionally add a short alias to `run_libfuzzer.sh`.

## Real bugs found by these harnesses

Documented in commit `8592a13`:

- Tag-parser `int` overflow (UB on long digit runs)
- `getInt` int64 overflow + non-digit UB
- `validateChecksum` could match an embedded `10=` instead of the trailer
- Trailer-length off-by-one (introduced and caught by an existing test
  during the validateChecksum fix)
- Missing `getUint64` accessor — `OrderId`/`Quantity` round-trip gap
